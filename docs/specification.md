# 概要

- マップ自動生成のコマンド選択式RPG
- マップは2次元グラフ形式で、各点を移動する
- 1ターン終了するたびに全体の勢力を更新する
- 敵のボスを倒せればクリア
- 自分の勢力がなくなればゲームオーバー

## 現在の実装(`src/game/`)について

上記の5行は初期のコンセプトのみで、ターン処理・勢力の更新式・コマンド体系・戦闘の仕様は本来まだ未確定だった。`src/game/` にはこれを遊べる形にするための最小限の実装が入っているが、以下は**すべて暫定の仮決め**であり、正式な設計として固まったものではない。数値は `src/game/constants.ts` に集約されており、随時調整される想定。CLI(`index.ts`)とブラウザ版(`web/`)の両方が同じ `src/game/` のロジックをそのまま利用しているため、以下の仕様はどちらの遊び方にも共通する。

### 勢力(フェクション)モデル
- `player`(自分)と `enemy`(敵ボス側)の2陣営のみ。各陣営は単一の数値 `power` を持つ(初期値100)。
- 複数陣営が入り乱れる本格的な勢力システムではなく、あくまで勝敗判定を成立させるための最小構成。

### ターンごとの勢力更新
- プレイヤーは毎ターン一律で `power` が減少する(遠征コスト、既定値 -1)。
- 移動先ノードの種別(`NodeType`)に応じた追加効果が発生する:
  - `battle`: プレイヤー・敵双方に乱数ダメージを与え合う
  - `event`: プレイヤーの `power` のみ乱数で増減する
  - `boss`: 下記の戦闘参照
  - `start` / `normal`: 追加効果なし
- 敵側の `power` は戦闘・ボス戦以外では変化しない(受動的な増減はない)。

### 戦闘
- 通常の `battle` ノード: 乱数ダメージをプレイヤー・敵の双方に適用する(`resolveSkirmish`)。
- `boss` ノード: 乱数を使わず、`player.power >= enemy.power` であれば撃破(クリア)、そうでなければボスから固定ダメージの反撃を受ける(`resolveBossEncounter`)。ノードは何度でも再訪可能なため、負けても勢力を回復・強化してから再挑戦できる。

### コマンド
- 現状は `move`(隣接ノードへの移動)のみ実装。将来のコマンド追加を見込み、`GameCommand` は判別可能なユニオン型として定義されている。
- 隣接していないノードへの `move` は移動自体は失敗するが、ターンは消費される(消耗ターン扱い)。

### 勝敗判定
- `enemy.power <= 0` になった時点で勝利。
- `player.power <= 0` になった時点でゲームオーバー。
- どちらも `advanceTurn` の末尾で毎ターン判定される(戦闘が発生していない消耗ターンだけでも敗北しうる)。

### 未確定・今後の検討事項
- 勢力の更新式(現在は「移動先ノード種別に応じた効果+一律の消耗」という単純なモデル)
- 移動以外のコマンド(休息、アイテム、撤退など)
- 複数陣営・勢力間の相互作用(現状はプレイヤーvs単一の敵のみ)
- 戦闘の詳細度(現状はダメージ量のみで、ステータスや装備などは一切ない)
